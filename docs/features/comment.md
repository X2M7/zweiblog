# 本地评论系统

ZweiBlog 的评论系统由主服务直接提供，评论、回复、审核状态和点赞数据保存在与博客相同的 MongoDB 实例中。运行时不加载 Waline、Gravatar 或其他第三方评论与头像服务。

## 访客功能

- 昵称、可选邮箱和可选个人主页
- Markdown、代码块与 TeX 公式
- 编辑/预览使用同一套安全渲染器，行内公式写作 `$E=mc^2$`，块级公式使用 `$$...$$`
- 多级回复、评论计数、分页和点赞
- 访客可自行选择是否在浏览器中记住昵称、邮箱和主页，并可随时清除；邮箱不会通过公开 API 返回
- 头像由昵称在浏览器本地生成，不会向外部头像服务发送邮箱或访问记录

## 审核与反滥用

后台的“评论管理”页面可以搜索评论、通过或退回待审、标记垃圾评论、回复和删除。系统使用 MongoDB 原子计数做持久化限流，服务重启或多实例部署不会重置计数。

除单 IP 限制外，每个评论目标还共享每小时 30 条、每天 100 条的跨 IP 上限，以降低 IPv6 地址轮换或代理池慢速占满回复槽位的风险。

公开评论 API 只接受 `/about`、`/link` 和真实存在的公开文章。站点关闭评论后，服务端也会同步拒绝读写；密码文章、密码分类以及不允许公开访问的隐藏文章不会开放评论，以免评论内容绕过文章权限。回复深度、单线程回复数和单次响应大小均有限制。

普通删除会原子清除正文、邮箱和主页，并暂存匿名结构占位；这样即使删除与访客回复同时发生，也不会产生失去父节点的回复。需要物理移除时，可在后台对已删除记录执行“永久清除”：没有后代的占位会从数据库移除，有后代时仍只保留匿名关系结构。迁移自 Waline 的记录会保留已脱敏幂等墓碑，避免旧数据库仍在时再次导入而复活；永久清除会把该标记移入独立的无隐私数据墓碑表。墓碑随站点备份导出和恢复。

在“系统设置 → 评论设置”中可以选择：

- `suspicious`：正常评论直接公开，多链接、异常重复内容等进入待审（默认）
- `all`：所有访客评论进入待审
- `off`：所有评论直接公开

可通过 `ZWEI_BLOG_COMMENT_FORBIDDEN_WORDS` 配置逗号分隔的违禁词。命中的评论会进入垃圾评论状态。

## 从旧 Waline 迁移

升级前请先保留数据库备份。升级后进入“系统设置 → 评论设置”，点击“导入旧 Waline 数据”。导入操作只读取旧数据库，并按旧记录 ID 幂等写入原生评论表；重复执行不会重复创建评论。迁移会校验完整回复链，并为旧版缺少 `rid` 的多层回复沿父链恢复根评论；孤儿、循环、跨页面回复、隐藏祖先下的已通过回复和每个主题超过 100 条的回复不会写成不可见或无界脏数据，而会逐条显示跳过原因。已永久删除记录的后代也不会在重跑迁移时复活。迁移只读取旧 `Users` 集合与评论的用户 ID 关系恢复站长回复标记，不信任评论行里的身份字段。

迁移、备份导入/导出以及评论审核或删除使用同一个 MongoDB 可续租维护锁，多实例部署也只允许一项评论写操作进入临界区。迁移进行时，新的前台评论会返回“数据忙，请稍后重试”，避免迁移与永久删除并发造成旧内容复活，也避免迁移和新回复合计突破线程上限。进程异常退出后，锁会在五分钟租期到期后自动释放。

请在开放原生评论前完成首次 Waline 导入。为保证线程上限和关系图可证明，目标评论集合一旦已有非迁移产生的原生评论，系统会拒绝再把 Waline 数据合并进去；已经开始过的幂等迁移仍可安全重跑。

在线迁移最多扫描 10 万条旧评论；更大的旧库应先停用 Waline，并使用离线数据库迁移和快照校验，避免把完整关系图装入应用进程内存。

Waline 的普通注册账号体系不会迁移为博客账号（本地评论不要求访客注册）；原评论中的昵称、合法主页和邮箱仍随评论保留，公开接口不会返回邮箱。无法唯一对应到现有文章的旧 `/post/*` 评论会先隔离在后台，避免文章删除、重命名或路径重用时误显示到另一篇文章。

默认读取同一 MongoDB 实例中的 `waline` 数据库。如旧数据库使用其他名称，可设置：

```bash
ZWEI_BLOG_LEGACY_WALINE_DB=旧数据库名
```

确认评论数量、回复关系和后台审核状态无误后，再决定是否归档旧数据库。迁移功能不需要 Waline 的 npm 包或运行进程。
